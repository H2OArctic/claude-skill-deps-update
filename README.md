# claude-skill-deps-update

Скилл для Claude Code: обновление зависимостей в Bun-проектах и монорепо без сюрпризов.

Обычное «обнови библиотеки» ломается на деталях, которые не видны в `bun outdated`:

- одна библиотека сидит в десятке `package.json` с разными диапазонами — в дереве оказываются две её копии;
- каретка на `0.x` разрешает только тот же минор, поэтому смена минора — фактический мажор, а выглядит как минор;
- часть версий запиннена точно намеренно — расширять диапазон нельзя, там уже ловили несовместимость;
- пакет вообще нельзя поднять, потому что его держит `peerDependencies` родителя;
- корневые `overrides` живут своей жизнью: часть уже не нужна, часть придётся добавить после `bun audit`,
  а часть вообще не доезжает до дерева — Bun переопределяет не все ветки, и старая копия остаётся стоять;
- после правок нужен честно пересобранный lockfile, иначе проверки идут против старого дерева.

Скилл разбирает всё это по фазам и заканчивается прогоном typecheck и тестов.

## Установка

```bash
git clone git@github.com:H2OArctic/claude-skill-deps-update.git ~/Developer/claude-skill-deps-update
cd ~/Developer/claude-skill-deps-update
bun install
bun bin/cli.ts install
bun bin/cli.ts hook        # автообновление, см. ниже
```

`install` кладёт симлинк `~/.claude/skills/deps-update` → `<репозиторий>/skill`, поэтому свежий коммит
становится скиллом сразу, без переустановки. Нужна независимая копия — `bun bin/cli.ts install --copy`.

В Claude Code скилл вызывается как `/deps-update`.

## Обновление

`hook` прописывает в `~/.claude/settings.json` хук `SessionStart`, который при старте сессии тихо
делает `git fetch` + fast-forward — руками `git pull` дёргать не нужно:

- проверка не чаще раза в 6 часов (метка в `~/.cache/claude-skill-deps-update/`, отдельная на каждый путь установки),
  так что обычный старт ничего не делает и ничего не стоит;
- `async: true` — сессия не ждёт сеть;
- молчит всегда, кроме факта обновления: одна строка `Скилл deps-update обновлён до X (a → b)`;
- незакоммиченные изменения или невозможный fast-forward — обновление пропускается, разбирается человек;
- выключить: `bun bin/cli.ts hook --remove`.

Настройки читаются и пишутся целиком, прежняя версия остаётся рядом как `settings.json.bak`,
права файла сохраняются.

Вручную — когда угодно:

```bash
cd ~/Developer/claude-skill-deps-update
bun bin/cli.ts update           # git pull --ff-only + актуализация установки
bun bin/cli.ts selfupdate --force   # то же, что делает хук, но игнорируя интервал
```

## Команды

| Команда | Что делает |
|---|---|
| `bun bin/cli.ts install [--copy] [--force] [--skills-dir <dir>] [--target <dir>]` | Установка (симлинк или копия) |
| `bun bin/cli.ts update` | `git pull --ff-only`, обновление копии, проверка симлинка |
| `bun bin/cli.ts selfupdate [--max-age <sec>] [--force] [--quiet]` | Тихий fetch + fast-forward, для хука |
| `bun bin/cli.ts hook [--remove]` | Включить/выключить автообновление через `SessionStart` |
| `bun bin/cli.ts status` | Где установлен, какая ревизия, состояние автообновления, версия Bun |
| `bun bin/cli.ts uninstall` | Снять установку (файлы репозитория не трогает) |
| `bun bin/cli.ts scan [args...]` | Запустить анализатор в текущем проекте |

## Анализатор

`skill/scripts/deps-scan.ts` — read-only инвентаризация воркспейса: ничего не ставит, не правит
`package.json` и не трогает lockfile. Запускать из корня проверяемого проекта:

```bash
bun ~/Developer/claude-skill-deps-update/skill/scripts/deps-scan.ts
```

Флаги: `--json` (машинный вывод), `--no-net` (без запросов в registry), `--no-why` (без чтения
установленного дерева и `bun why` — быстрее, но без вердиктов и фактических версий),
`--cwd <path>` (другой корень).

Что выдаёт:

1. **Расхождения версий** — одна библиотека с разными диапазонами по воркспейсам (`peerDependencies`
   внутренних пакетов не считаются расхождением: они намеренно широкие).
2. **Дубли в дереве** — объявленный пакет установлен в нескольких версиях сразу (`bun pm ls --all`).
   Транзитивные дубли — счётчиком: их в монорепо десятки, и это обычно норма.
3. **Кандидаты на обновление** с классом риска: `PATCH`, `MINOR`, `MAJOR`, `0.x MINOR — ЛОМАЮЩЕЕ`,
   `0.0.x PATCH — ЛОМАЮЩЕЕ`, `PRERELEASE`. Рядом — что записано в `package.json`, что реально стоит
   в дереве и максимум внутри диапазона (подтянется сам при пересборке lockfile). Если latest уже
   установлен, это помечается: правка диапазона там ничего не обновляет.
4. **Семейства** — скоуп (`@scope/*`) или фреймворк вместе со своими плагинами и адаптерами.
   Обновлять только целиком: полуобновлённое семейство падает не на установке, а в рантайме.
5. **Overrides / resolutions** — число копий в дереве и вердикт-гипотеза по каждому:
   - `REDUNDANT_NOW` — родители сами требуют не меньше, кандидат на удаление;
   - `RAISES_FLOOR` — поднимает минимум внутри допустимого диапазона, похоже на security-override;
   - `BREAKS_CEILING` — просит версию выше той, что родитель считает совместимой; часто фикция —
     если копий несколько, старая всё равно осталась в дереве и потолок никто не ломал;
   - `NOT_APPLIED` — ни одна установленная копия не попадает в override: lockfile разошёлся с `package.json`;
   - плюс пометка, если пакет есть и в `overrides`, и в прямых зависимостях — такие правятся синхронно.
6. **Deprecated** пакеты, у которых сам `latest` помечен устаревшим.
7. **Ручная проверка** — сложные диапазоны (`>=2 <3`, `a || b`) и ошибки registry: скрипт не угадывает.

Вердикты по overrides — эвристика по диапазонам, а не факт: Bun переопределяет не все ветки дерева.
Что override делает на самом деле, показывает только эксперимент (в скилле он описан пошагово):
снять все overrides разом → `bun install` → сравнить `bun audit` и число копий.

## Требования

- Bun ≥ 1.2 (нужны `bun outdated`, `bun why`, `bun audit`, `bun info`, `bun pm ls`). Разрабатывалось и
  проверялось на 1.3.14.
- Проект с `package.json`; `workspaces` не обязательны — для одиночного пакета работает так же.
- Доступ к npm registry (или свой через `NPM_CONFIG_REGISTRY`).
